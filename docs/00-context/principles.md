# Product and Engineering Principles

**Status:** Foundation / Draft  
**Project:** APOTHEM AI  
**Canonical domain:** `apothemai.com.br`

## 1. Intelligence must connect to operations
A response that cannot use or affect business context has limited operational value.

## 2. Least privilege before maximum autonomy
Agent capability is constrained by explicit permissions, tool policies and approval requirements.

## 3. Human approval is a product primitive
Approval is not a temporary limitation of model quality. It is a permanent governance mechanism for risk-sensitive operations.

## 4. Models are replaceable providers
Provider capabilities matter, but the APOTHEM domain model should survive provider changes.

## 5. Every important execution is traceable
The system should explain which agent version, model decision, knowledge sources, tools and approvals participated in an outcome.

## 6. Deterministic logic stays deterministic
Do not ask a language model to decide facts/rules that can be reliably enforced in code.

## 7. AI behavior must be evaluated
“Works in my chat” is not a quality standard. Maintain datasets and measurable acceptance criteria.

## 8. Multi-tenancy is structural
Tenant isolation is not a query convention added later.

## 9. Complexity must earn its place
Do not add distributed infrastructure because the vision is large. Start modular and extract based on evidence.

## 10. Solutions must strengthen the platform
Customer-specific work should create reusable platform primitives where possible.
